Installation et premier run

Vous partez de rien : pas de projet, pas de configuration. Vous installez le paquet loom-ia, seul, puis vous avancez commande par commande jusqu'à faire répondre un premier agent. Quand loom refuse une commande, son message dit ce qui manque : c'est lui qui vous guide.

Ce qu'il vous faut

  • Un terminal sous Linux.
  • uv, l'outil qui installe Python et les paquets d'un projet. Si vous ne l'avez pas, l'étape 1 l'installe.

Pas besoin d'installer Python vous-même, ni d'avoir une clé d'API : le premier agent tourne sur un modèle simulé, fourni avec loom.

1 Installer uv

$ curl -LsSf https://astral.sh/uv/install.sh | sh

Fermez puis rouvrez le terminal, et vérifiez :

$ uv --version

Si uv était déjà installé, passez à l'étape suivante.

2 Créer le dossier du projet

Toute la formation se passe dans un seul dossier, plomberie-dupont : c'est le projet de l'assistant que vous allez construire pour une entreprise de plomberie.

$ uv init --bare --python 3.14 plomberie-dupont
Initialized project `plomberie-dupont` at `/home/jean/plomberie-dupont`
$ cd plomberie-dupont
$ ls
pyproject.toml

uv a créé le dossier et un fichier pyproject.toml, qui tiendra la liste des paquets du projet. Pour l'instant, elle est vide. --python 3.14 indique la version de Python voulue : loom-ia demande Python 3.14 ou plus récent, et uv le téléchargera s'il ne le trouve pas sur la machine.

3 Installer loom-ia

Le paquet s'appelle loom-ia sur PyPI. On l'installe seul, sans option :

$ uv add loom-ia
Using CPython 3.14.6
Creating virtual environment at: .venv
Resolved 22 packages in 625ms
Installed 20 packages in 57ms
 …
 + loom-ia==2.0.11
 + pydantic==2.14.1
 + pyyaml==6.0.3
 …
$ ls -A
.venv  pyproject.toml  uv.lock
  • .venv/ est l'environnement Python du projet : Python 3.14, loom-ia et les quelques paquets dont il dépend. Rien n'est installé ailleurs sur votre machine.
  • pyproject.toml contient maintenant la ligne "loom-ia>=2.0.11", et uv.lock note les versions exactes installées.

Ce paquet de base suffit pour tout ce module. Plus tard, vous lui ajouterez des options, appelées « extras », pour brancher Claude, une base de données ou un serveur web. Chacune viendra au moment où vous en aurez besoin.

4 Activer l'environnement et trouver la commande loom

loom-ia a installé une commande, loom, dans l'environnement du projet. Pour pouvoir la taper directement, activez cet environnement :

$ source .venv/bin/activate
$ loom --version
loom 2.0.11

L'activation vaut pour le terminal ouvert. Dans un nouveau terminal, revenez dans le dossier du projet et relancez source .venv/bin/activate. Toutes les commandes de la formation supposent l'environnement activé. (Sans l'activer, on peut aussi préfixer chaque commande par uv run : uv run loom --version.)

Voyons ce que sait faire cette commande :

$ loom --help
usage: loom [-h] [--version] [--config CONFIG] [--profile {dev,prod}]
            [--env-file ENV_FILE | --no-env-file]
            {validate,run,state,resume,replay,inspect,eval,approve,reject,serve,mcp,keys,report,sessions,worker,retention,storage,schema} ...

Agents loom en ligne de commande

positional arguments:
  {validate,run,state,resume,replay,inspect,eval,approve,reject,serve,mcp,keys,report,sessions,worker,retention,storage,schema}
    validate            vérifie la config et monte les agents
    run                 lance un run et attend sa fin
    …

Beaucoup de commandes. Pour commencer, deux suffisent : loom run, qui lance un agent, et loom validate, qui vérifie la configuration.

5 Essayer de lancer un agent

On voudrait un agent nommé assistant, à qui l'on dit bonjour. loom run prend le nom de l'agent, puis la demande entre guillemets :

$ loom run assistant "Bonjour, qui es-tu ?"
Configuration : Fichier illisible : [Errno 2] No such file or directory: '/home/jean/plomberie-dupont/loom.yaml'

Refusé, et c'est normal : nous n'avons encore rien décrit. loom cherche dans le dossier courant un fichier de configuration, loom.yaml, qui n'existe pas.

loom n'invente rien : un agent n'existe que si vous l'avez décrit dans des fichiers. Il en faut deux, que l'on va créer l'un après l'autre :

6 Créer loom.yaml : le modèle

Un agent a besoin d'un modèle de langage (un LLM, comme Claude ou GPT) pour comprendre la demande et répondre. loom ne contient aucun LLM : il se branche sur ceux des fournisseurs. Mais pour apprendre, il fournit un modèle simulé, qui répond sans compte, sans clé et sans réseau. C'est lui que l'on déclare.

Créez le fichier loom.yaml avec votre éditeur de texte, ou directement dans le terminal en copiant ce bloc entier :

$ cat > loom.yaml <<'EOF'
version: 1

models:
  - id: SIMULE
    sdk: fake
    model: fake-1
EOF

Le fichier est écrit en YAML : chaque ligne est une clé, deux-points, une valeur ; les espaces en début de ligne indiquent ce qui est rangé dans quoi ; un tiret commence un élément de liste.

version: 1La version du format de configuration. Toujours 1, et obligatoire.
models:La liste des modèles que vos agents pourront utiliser. Ici, un seul.
- id: SIMULELe nom que vous donnez à ce modèle. Les agents le désigneront par ce nom.
sdk: fakeLe type de modèle. fake est le modèle simulé de loom ; plus tard vous utiliserez anthropic pour Claude.
model: fake-1Le nom du modèle chez le fournisseur. Pour le modèle simulé, n'importe quel nom convient.

Vérifiez la configuration :

$ loom validate
Configuration : Dossier d'agents introuvable : /home/jean/plomberie-dupont/agents

Le fichier est accepté, et loom passe à la suite : il cherche les agents dans un dossier agents/, qui n'existe pas encore.

7 Créer le dossier des agents

$ mkdir agents
$ loom validate
…
0 agent(s) monté(s) sans erreur.
$ loom run assistant "Bonjour, qui es-tu ?"
Agent 'assistant' inconnu (agents : aucun)

La configuration est valide, mais le dossier est vide : loom ne connaît aucun agent. Chaque fichier .yaml de ce dossier décrit un agent ; il reste à écrire celui de l'assistant.

8 Créer agents/assistant.yaml : l'agent

$ cat > agents/assistant.yaml <<'EOF'
name: assistant

main:
  model: SIMULE
  system: Tu es l'assistant de la Plomberie Dupont. Tu réponds en français.
EOF
name: assistantLe nom de l'agent : celui que vous tapez après loom run.
main:Le modèle principal de l'agent, celui qui lit la demande et répond. loom l'appelle l'orchestrateur, parce que c'est lui qui décidera plus tard d'utiliser des outils. Les deux lignes suivantes, décalées de deux espaces, le décrivent.
model: SIMULELe modèle à utiliser, désigné par le nom donné dans loom.yaml.
system: …Le prompt système : les consignes données au modèle, qui lui disent qui il est et comment répondre.
 
$ loom validate
Config     : loom.yaml
Profil     : aucun (ni --profile, ni LOOM_PROFILE, ni 'profile:') ; surcharges : aucune
Env        : aucun (/home/jean/plomberie-dupont/.env)
Modèles    : SIMULE
Agents     : assistant
Outils     : aucun
Paquets    : forge (loom-ia 2.0.11) (groupe loom_ia.tools)
Journal    : memory
Artefacts  : memory
Idempotence: journal
File       : asyncio
Bus        : memory (les nouvelles ne sortent pas de ce process)
Chiffrement: aucun (contenus en clair au repos)
Rétention  : aucune (rien ne s'efface)
Télémétrie : logs INFO (console) ; exports sans contenu (metadata) ; pas d'échanges bruts
    collecteur : aucun — rien ne sort du journal que les logs
Clés d'API : aucune (API REST ouverte)
  assistant : modèle SIMULE, 0 outil(s) Python

1 agent(s) monté(s) sans erreur.

Cette fois, loom affiche ce qu'il a compris. Pour l'instant, regardez trois lignes : Modèles : SIMULE, Agents : assistant, et la dernière, qui dit que l'agent est prêt. Les autres décrivent des fonctions de loom que vous n'avez pas configurées ; elles gardent leur réglage par défaut, et la formation les présente une à une.

Si loom refuse le fichier

Le message nomme le fichier et la clé en cause. Les causes les plus courantes :

  • main — Field required : la clé main manque, ou elle est mal écrite.
  • modèle 'SIMULE' non déclaré : le nom cité dans l'agent n'est pas celui de loom.yaml. Les majuscules comptent.
  • YAML invalide : souvent une indentation décalée, ou une tabulation au lieu d'espaces.

9 Le premier run

$ loom run assistant "Bonjour, qui es-tu ?"
2026-10-24 09:29:23 INFO     loom_ia.engine.loop — Modèle SIMULE (rôle main) : 0.00 s, 109 tokens, 0.00000 $ […]
2026-10-24 09:29:23 INFO     loom_ia.engine.loop — Transition ready_for_model → completed (agent assistant) […]
Écho : Bonjour, qui es-tu ?

Statut     : completed · itérations : 1 · tokens : 77/32 · coût : 0.0000 $
Run        : 01a16cd0-7595-70ae-af87-81374451caeb

L'agent a tourné. Un run, c'est une exécution de l'agent pour une demande. Ce que vous voyez, de haut en bas :

  • Deux lignes INFO : loom raconte ce qu'il fait. Il a appelé le modèle SIMULE en tant que main, puis le run est passé à l'état completed, terminé.
  • Écho : Bonjour, qui es-tu ? : la réponse de l'agent. Le modèle simulé ne réfléchit pas : tant qu'on ne lui a pas écrit de réponse, il renvoie la demande.
  • Le bilan : le statut, le nombre d'appels au modèle (itérations), les tokens consommés (en entrée et en sortie), le coût, nul ici, et l'identifiant du run.

Récapitulatif

Pour faire tourner un agent, il a fallu :

  1. installer le paquet loom-ia dans un projet uv et activer son environnement ;
  2. déclarer un modèle dans loom.yaml ;
  3. décrire l'agent dans un fichier du dossier agents/ ;
  4. lancer loom run <agent> "<demande>".

Le module 1 part de ces deux fichiers. Il fait vraiment parler l'agent, le branche sur Claude, garde la trace de ses runs et lui donne un premier outil.
