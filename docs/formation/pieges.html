Pièges et dépannage

Les pièges rencontrés pendant la rédaction de la formation, classés par thème. Pour chacun : ce que vous voyez (le message exact de loom quand il y en a un), pourquoi, quoi faire, et l'exercice qui en parle. Les messages viennent de loom-ia 2.0.11.

Un réflexe avant tout : loom validate. Il refuse une configuration incohérente avant le moindre run, et son message nomme le fichier et la clé en cause. Codes de sortie de toute la CLI : 0 succès, 1 run qui n'aboutit pas (échec, pause), 2 configuration ou demande refusée.

Thèmes : Installation et YAML, Configuration et validation, Outils, Modèles et clés, Sessions et journal, Outils MCP, Rôles, sous-agents et vision, Contrats, juges et politiques, Approbations, idempotence et reprise, Coûts et budgets, API REST et serveur MCP, Déclencheurs, file et bus, Clients et données sensibles, Observabilité et rejeu, Évals et tests, Sources d'outils et forge.

Installation et YAML

Ce que vous voyezPourquoi, et quoi faireVoir
uv affiche Failed to hardlink files; falling back to full copyLe cache de uv et le dossier du projet sont sur deux systèmes de fichiers différents (un disque mémoire, une autre partition) : uv copie les fichiers au lieu de les lier. Sans conséquence pour loom. Pour ne plus le voir : export UV_LINK_MODE=copy, ou travaillez sous un dossier du même disque que ~/.cache/uv. Un disque mémoire est vidé au redémarrage : n'y gardez pas le projet de la formation.Module 1, 1.1
Fichier illisible : … No such file or directory: '…/loom.yaml'Vous n'êtes pas dans le dossier du projet, ou loom.yaml n'existe pas encore. loom cherche ce fichier dans le dossier courant (ou à l'endroit donné par --config).Module 1, 1.3
Dossier d'agents introuvable : …/agents ou Agent 'assistant' inconnu (agents : aucun)Le dossier agents/ manque, ou le fichier de l'agent n'y est pas. Chaque fichier .yaml de ce dossier décrit un agent.Module 1, 1.3
YAML invalide : mapping values are not allowed hereUn texte contient un deux-points suivi d'une espace (« Source : … ») sans être entre guillemets : YAML le prend pour une nouvelle clé. Mettez le texte entre guillemets. Un texte qui contient lui-même des guillemets doubles (du JSON, par exemple) se met entre apostrophes.Module 1, 1.8
Module 7, 7.2
YAML invalide : … found character '\t' that cannot start any tokenUne tabulation sert d'indentation. YAML n'accepte que des espaces : configurez l'éditeur pour remplacer les tabulations.Module 1, 1.3
Une expression régulière ne reconnaît plus rien après passage dans le YAMLDans un texte entre guillemets doubles, la barre oblique inverse est un caractère d'échappement : \d s'écrit \\d.Module 7, 7.2
Après uv add "loom-ia[openai]", Claude ne fonctionne plusLa liste d'extras écrite remplace l'ancienne dans pyproject.toml. Redonnez-la en entier : uv add "loom-ia[anthropic,openai]".Module 3, 3.2

Contrats, juges et politiques

Ce que vous voyezPourquoi, et quoi faireVoir
main.output — Extra inputs are not permittedLe contrat et le juge de la réponse finale se déclarent au niveau de l'agent (output:, judge:), pas sous main.Module 7, 7.1
Un rôle refusé par son contrat n'arrête pas le runAvec on_failure: fail sur un rôle, c'est l'appel du rôle qui échoue : l'orchestrateur reçoit l'erreur et continue. Pour qu'un échec arrête tout le run, posez le contrat sur la réponse finale (output de l'agent).Module 7, 7.3
Avec --judges skip, un montant inventé passeSauter les juges sert aux essais. Le contrat ne vérifie que la forme ; seul le juge vérifie le fond. --judges skip est refusé en profil prod.Module 7, 7.4
… : même modèle que la sortie qu'il évalue (REDACTEUR) : juge corréléUn juge sur le même modèle que la sortie jugée a les mêmes angles morts. Avertissement en développement, erreur en profil prod : choisissez un autre modèle. Même règle pour un juge bloquant échantillonné (sample inférieur à 1).Module 7, 7.6
Module 7, 7.4
un outil Python n'a pas de juge : un juge porte sur la réponse finale (judge: de l'agent) ou sur un rôle (roles[].judge)Le résultat d'un outil se contrôle par son contrat (output), pas par un juge.Module 7, 7.5
loom.require_tool impose l'outil même pour « Bonjour »Cette politique s'applique à chaque demande. Limitez-la à ce qui en a besoin, ou acceptez qu'un simple bonjour déclenche une lecture.Module 7, 7.7
La réponse cite une source que l'agent n'a pas pu lireLe modèle peut répondre de mémoire en citant une source. Une consigne dans le prompt ne suffit pas : imposez la lecture par une politique (loom.require_tool) et faites vérifier le fond par un juge.Module 1, 1.8

Approbations, idempotence et reprise

Ce que vous voyezPourquoi, et quoi faireVoir
outil 'envoyer_email' en approval: always — une approbation exige un journal durable (jsonl ou sqlite ou postgres), pas 'memory' (#28)Un run en pause doit survivre à la commande qui l'a lancé : déclarez un journal sur disque.Module 8, 8.1
--arguments fait refuser l'appelLes arguments donnés à l'approbation remplacent tous ceux du modèle ; ils ne se fusionnent pas. Donnez l'objet complet.Module 8, 8.3
loom approve refuse une demande expirée (code 2)Après expires_in, la demande ne peut plus être tranchée. Relancez le run avec loom resume : il se conclut selon on_expiry.Module 8, 8.3
ce run est mené ailleurs : réessayer après l'échéanceJuste après un plantage, le run est encore « tenu » par le process mort pendant la durée de sa concession (60 s par défaut). Attendez l'échéance indiquée, puis relancez loom resume.Module 8, 8.5
État inconnu : l'exécution de cet outil a été interrompue et il a peut-être produit son effet. Il n'a pas été relancé automatiquementUn outil à effet de bord interrompu n'est jamais relancé à l'aveugle. Vérifiez à la main (l'e-mail est-il parti ?) avant de le rappeler. Une fenêtre de quelques millisecondes subsiste entre l'effet et sa mémorisation ; un service externe qui accepte une clé d'idempotence la referme.Module 8, 8.5
… il leur faut un magasin d'idempotence partagé et durable (sqlite ou postgres ou redis), pas 'journal' (#49)Une clé d'idempotence métier (qui vaut pour tous les runs) demande storage.idempotency en sqlite, postgres ou redis.Module 8, 8.6
Jean doit approuver deux fois un e-mail qui ne part qu'une foisL'approbation passe avant l'idempotence : la seconde demande est posée, puis l'envoi est reconnu comme déjà fait. Prévenez l'approbateur, ou évitez de relancer la même demande.Module 8, 8.6
Le run a échoué sur son délai, et pourtant l'e-mail est partiLe timeout du run rend la main, il n'interrompt pas une fonction synchrone en cours. Ne comptez pas sur le délai pour empêcher un effet de bord.Module 8, 8.7
Pas de commande loom pour annuler un runL'annulation passe par Python (Loom.cancel()), l'API REST (POST /v1/runs/{id}/cancel) ou l'outil MCP cancel.Module 8, 8.8
Module 10, 10.7
Un run approuvé depuis le même programme reste bloquéApprouver dès l'événement approval.requested, dans le process qui mène le run, arrive avant la fin de la mise en pause : la décision est écrite, mais la reprise est perdue. Attendez la transition vers paused, ou relancez avec loom resume.Module 10, 10.3
