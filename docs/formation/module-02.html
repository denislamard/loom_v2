Module 2 : Outils Python

L'assistant lit des pages web, mais il compte encore de tête et ne connaît aucun devis. Dans ce module, vous lui écrivez vos propres outils en Python : un calcul de prix TTC, la recherche d'un devis, une étiquette en image. Vous verrez comment loom les décrit au modèle, ce qu'il fait quand un outil échoue ou se trompe d'arguments, et comment il range les gros résultats et les fichiers.

2.1 Écrire un premier outil Python

D2

Pourquoi

Un modèle de langage calcule mal : il peut se tromper d'un euro sur une TVA, ou inventer un arrondi. Jean veut que les montants viennent d'un calcul exact. La règle de loom : le modèle propose, le code calcule. Le calcul devient un outil, une fonction Python que le modèle demande et que loom exécute.

Mise en place

1. Écrire l'outil. Créez le fichier outils.py à la racine du projet, à côté de loom.yaml :

from loom_ia.tools import toolImporte le décorateur tool, fourni par loom.
@toolTransforme la fonction qui suit en outil que l'agent peut appeler. Son nom (prix_ttc) devient le nom de l'outil.
montant_ht: float, taux_tva: float = 20.0Les paramètres et leur type. loom en tire le schéma de l'outil : la liste des arguments, leur type, ceux qui sont obligatoires. taux_tva a une valeur par défaut, il est donc facultatif.
"""Calcule la TVA…"""La docstring devient la description que lit le modèle pour savoir quand appeler l'outil. Elle est obligatoire : sans elle, loom refuse l'outil.
return {…}Le résultat. Un dictionnaire est transmis au modèle en JSON ; un texte (str) serait transmis tel quel.

Pour voir le schéma que loom a tiré de la signature, demandez-le à Python :

$ python -c "
import json
from outils import prix_ttc
print(json.dumps(prix_ttc.spec.input_schema, ensure_ascii=False, indent=2))"
{
  "additionalProperties": false,
  "properties": {
    "montant_ht": {
      "title": "Montant Ht",
      "type": "number"
    },
    "taux_tva": {
      "default": 20.0,
      "title": "Taux Tva",
      "type": "number"
    }
  },
  "required": [
    "montant_ht"
  ],
  "type": "object"
}

C'est ce schéma, avec le nom et la description, que le modèle reçoit. "required": ["montant_ht"] : le montant HT est obligatoire. "additionalProperties": false : aucun autre argument n'est accepté.

2. Charger le fichier et préparer le modèle simulé. Deux changements dans loom.yaml : la clé imports dit à loom de charger outils.py au démarrage, et le script du modèle simulé est remplacé par celui de ce module. Ce script contient d'avance un scénario par exercice ; chaque exercice dira lequel il utilise.

lignes ajoutées ou remplacées

imports: [outils]Les modules Python à charger au démarrage. outils désigne le fichier outils.py, à côté de loom.yaml. En le chargeant, loom enregistre les fonctions marquées @tool.
# 2.1 : …Un commentaire : YAML ignore tout ce qui suit #. Il sert ici à repérer les scénarios.
tool_calls:Vu au module 1 : les outils que le modèle simulé demande, avec leurs arguments. Ici, prix_ttc avec montant_ht: 1250 et taux_tva: 10.

ligne ajoutée

- python: prix_ttc désigne l'outil par son nom. Sans imports, on peut aussi écrire le chemin complet, - python: outils:prix_ttc (module, deux-points, fonction).

Ce qu'il faut comprendre

  • Une erreur d'outil n'arrête pas le run : elle devient un résultat d'erreur, que le modèle reçoit comme n'importe quel résultat. Il peut alors corriger son appel ou expliquer le problème. Le run se termine normalement (completed).
  • Avec ToolError, c'est vous qui choisissez le message. Une autre exception (une erreur de programmation, par exemple) est rattrapée aussi, mais le modèle ne reçoit que son type et son texte bruts. Avec devis = DEVIS[numero] à la place du test, l'inspection afficherait : (erreur) Erreur de l'outil chercher_devis : KeyError: 'D-2026-999'.

2.3 Le contrat d'un outil et ses réglages

D1D5

Pourquoi

Un outil peut être lent : une page web qui ne répond pas, un logiciel distant en panne. Jean ne veut pas que l'agent attende indéfiniment. Chaque outil a donc un délai, réglable sans toucher à son code.

Ce qu'il faut comprendre d'abord

Pour loom, tout outil, qu'il vienne de votre code, d'un paquet ou d'un serveur extérieur (module 5), suit le même contrat :

NomCe que le modèle demande : prix_ttc.
DescriptionCe qui dit au modèle quand l'utiliser : la docstring.
Schéma d'entréeLes arguments attendus, tirés de la signature.
CapacitésCe que loom doit savoir pour l'exécuter sans risque : son délai, la taille au-delà de laquelle son résultat est mis de côté, s'il agit sur le monde extérieur, s'il faut l'accord d'un humain…

Les capacités ont une valeur par défaut, que l'outil peut fixer lui-même (@tool(timeout=10)) et que l'agent peut surcharger dans sa liste tools. Les surcharges possibles :

timeoutDélai d'exécution, en secondes. Par défaut 30 s ; loom.fetch_page fixe lui-même 45 s.
offload_overTaille, en caractères, au-delà de laquelle le résultat est mis de côté (exercice 2.7).
side_effects, approval, idempotentLes outils qui agissent sur le monde extérieur, et l'accord humain : module 8.
outputUn contrôle de ce que l'outil rend : module 7.

Mise en place

Pour voir un délai tomber, donnez à fetch_page un délai impossible à tenir, un centième de seconde :

ligne ajoutée

La ligne timeout est décalée sous - python: loom.fetch_page : elle règle cet outil-là, et lui seul. Le scénario utilisé est celui marqué # 2.3.

Exécution

    outil fetch_page — 267 ms (erreur)
      · arguments : {"url": "https://www.impots.gouv.fr/professionnel/questions/quel-taux-de-tva-appliquer-pour-les-t…
      · résultat  : (erreur) Délai dépassé : pas de réponse en 0.01 s.

À retenir

  • Un délai dépassé est une erreur d'outil comme une autre : le modèle la reçoit, le run continue.
  • La durée affichée (ici 267 ms) peut dépasser le délai : c'est le temps que l'outil a mis à rendre la main après l'interruption. Une fonction Python ordinaire (non async) tourne à part : loom n'attend plus son résultat, mais il ne peut pas l'arrêter en plein calcul.
  • Retirez la ligne timeout: 0.01 avant la suite.

2.6 Borner la boucle

A4

Pourquoi

Un agent peut enchaîner les outils longtemps, et chaque appel au modèle coûte. Il faut une limite au nombre de tours.

Mise en place

Ajoutez max_iterations à l'agent, avec une valeur volontairement trop basse :

ligne ajoutée

max_iterations: 1Le nombre maximal d'appels au modèle qui peuvent demander des outils. Sans cette clé, la limite est de 10.

Le scénario # 2.6 a besoin de deux tours d'outils : chercher le devis, puis recalculer le prix. Sa deuxième réponse porte une clé nouvelle, forced :

forced: …Pour le modèle simulé : le texte qu'il rend si loom lui interdit d'appeler des outils. Un vrai modèle, lui, rédige une réponse de lui-même.

Exécution

$ loom run assistant "Recalcule le devis D-2026-042 à 10 %." --session borne
Le devis D-2026-042 est à 1 533,33 € HT. Je n'ai pas eu le temps de recalculer le TTC à 10 % ; demandez-le-moi à nouveau.

Statut     : completed · itérations : 2 · tokens : 2917/121 · coût : 0.0000 $
Run        : 01a16dee-725e-77a6-8e3a-61a9c47515c0
$ jq -r 'select(.type=="run.transitioned") | "\(.payload.from_state) → \(.payload.to_state) (\(.payload.cause_type))"' data/default/borne.jsonl
ready_for_model → awaiting_tools (model.responded)
awaiting_tools → finalizing (tool.completed)
finalizing → completed (model.responded)

La commande jq affiche les changements d'état du run, écrits dans le journal (événements run.transitioned).

Ce qu'il faut comprendre

  • Après le premier outil, la limite est atteinte. Au lieu de revenir à ready_for_model (prêt pour un nouvel appel), le run passe à finalizing : loom fait un dernier appel au modèle en lui interdisant les outils, et lui demande de répondre avec ce qu'il a déjà.
  • C'est la réponse forcée : l'agent dit ce qu'il a fait et ce qui reste à faire, au lieu de s'arrêter sans rien dire. Elle compte comme une itération de plus : 2 au total.

Passez maintenant max_iterations à 5, la valeur que garde la suite de la formation, et relancez :

$ loom run assistant "Recalcule le devis D-2026-042 à 10 %." --session sans-borne
À 10 %, le devis D-2026-042 passerait à 1 686,66 € TTC.

Statut     : completed · itérations : 3 · tokens : 4566/176 · coût : 0.0000 $
Run        : 01a16dee-7d26-76c7-a297-1e9f4f1a0388

Piège : une clé écrite deux fois

Si vous ajoutez une seconde ligne max_iterations au lieu de modifier la première, loom refuse le fichier plutôt que de garder l'une des deux en silence :

Configuration : /home/jean/plomberie-dupont/agents/assistant.yaml: clé 'max_iterations' donnée deux fois dans le même objet (lignes 3 et 5) : la seconde écraserait la première en silence

2.7 Mettre de côté un gros résultat

D6G2

Pourquoi

Une page web peut faire des dizaines de milliers de caractères. Tout envoyer au modèle à chaque tour coûte cher et noie l'essentiel. loom met donc de côté les gros résultats : le modèle reçoit un aperçu et une référence, et lit la suite s'il en a besoin.

Mise en place

Le seuil se règle par outil avec offload_over, en caractères. Par défaut, il est de 50 000 caractères (20 000 pour loom.fetch_page). Un devis est bien plus court : pour l'exercice, on abaisse le seuil de chercher_devis à 100 caractères.

ligne ajoutée

Ce qu'il faut comprendre

  • Le résultat dépasse 100 caractères : il est déporté. Le modèle reçoit un aperçu (pour un JSON, ses clés et le début de leurs valeurs ; pour un texte, ses 2 000 premiers caractères) et une note qui donne la référence artifact://… et la marche à suivre.
  • Le modèle lit la suite avec artifact_read, par morceaux (offset, limit). Cet outil n'est proposé qu'après un premier déport.
  • Les fichiers vivent dans le stockage d'artefacts, séparé du journal, qui n'en garde que la référence. Avec un journal JSONL dans data/, ce stockage est par défaut le dossier data/.artifacts/, rangé par client puis par session. Le nom du fichier est l'empreinte de son contenu.
  • Le script du modèle simulé contient la référence en dur, car elle est connue d'avance : la même session et le même contenu donnent la même empreinte. Un vrai modèle la recopie depuis la note. Si vous avez modifié le carnet de devis, l'empreinte change, et artifact_read répond que la référence est inconnue en donnant la bonne.
  • Retirez la ligne offload_over: 100 avant la suite.

2.8 Rendre une image

D8G3G2

Pourquoi

Jean colle sur chaque dossier papier une étiquette de couleur : orange pour un devis envoyé, vert pour un devis accepté. Il voudrait que l'agent la fabrique. Un outil peut rendre autre chose que du texte : ici, une image.

Mise en place

Ajoutez l'outil etiquette_devis à la fin de outils.py. La petite fonction png_uni fabrique une image d'une seule couleur sans bibliothèque d'image ; inutile d'en comprendre le détail.

Ce qu'il faut comprendre

  • Selon ce qu'il renvoie, un outil produit un résultat différent : un str donne du texte, un dictionnaire ou une liste du JSON, une Image un fichier. (Pour mêler plusieurs blocs, texte, données et fichiers, dans un même résultat, un outil peut aussi construire lui-même un ToolOutput, la forme que loom donne à tout résultat.)
  • Une image n'entre pas dans le journal : elle est rangée dans le stockage d'artefacts, comme le résultat déporté de l'exercice 2.7, et le journal garde sa référence. Le champ origin dit d'où vient un fichier : tool_output pour un outil, offload pour un résultat déporté.
  • Le modèle reçoit une référence à l'image. Un modèle capable de voir les images (capacité vision, module 6) peut en recevoir le contenu.
  • Le dossier etiquettes/ n'est qu'une copie de travail : supprimez-le ou ajoutez-le à .gitignore.
